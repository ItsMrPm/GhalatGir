# غلط‌آزمون — بک‌اند + دیتابیس (نسخه‌ی قابل‌اجرا)

## این چیه؟
تکمیل‌شده‌ی پروتوتایپ `prototype.html` طبق سندِ `architecture.md`: یک بک‌اند واقعی
و کامل (auth، ثبت غلط، تولید آزمون هوشمند، موتور SRS، آنالیتیکس) + دیتابیس،
و فرانت‌اندی که به‌جای داده‌ی هاردکد، از همین بک‌اند داده می‌گیرد.

## چرا Flask/SQLite به‌جای Django/DRF/PostgreSQL/Celery؟
سندِ معماری دقیقاً Django+DRF+PostgreSQL+Redis+Celery را پیشنهاد داده. محیطی که
من (Claude) این پروژه رو توش ساختم دسترسی به اینترنت نداره، پس نصب و اجرای
هیچ‌کدوم از این پکیج‌ها ممکن نبود — فقط چیزهایی که از قبل نصب بودن رو داشتم:
Python استاندارد (شامل `sqlite3`)، Flask، PyJWT، Werkzeug.

**تصمیم:** schema و منطق (الگوریتم تولید آزمون، امتیاز اولویت، زمان‌بندی مرور
فاصله‌دار) را دقیقاً طبق سند پیاده کردم، فقط framework عوض شد. جدول‌به‌جدول و
اندپوینت‌به‌اندپوینت با `architecture.md` قابل تطبیقه. کد رو همین‌جا اجرا و
تست کردم (register → login → ثبت غلط → تولید آزمون → پاسخ‌دهی → بروزرسانی SRS →
آنالیتیکس) و همه چیز کار می‌کنه.

اگر بعداً خواستی روی Django/PostgreSQL/Celery واقعی مهاجرت کنی، schema.sql و
منطق سرویس‌ها (`services/*.py`) تقریباً بدون تغییر قابل پورت هستن — فقط لایه‌ی
ORM و routing عوض می‌شه.

### چیزهایی که ساده‌سازی شدن (و چرا)
| بخش سند | در این نسخه |
|---|---|
| Auth با OTP پیامکی | phone_number + password (نیاز به گیت‌وی SMS واقعی داشت) |
| Celery Beat شبانه برای priority_score | همون تابع، ولی sync و بلافاصله بعد از هر تغییر اجرا می‌شه (در این مقیاس داده فرقی حس نمی‌شه) |
| Cloudinary/S3 برای عکس سؤال | فیلدهای `image_url` و `answer_image_url` متنی (لینک) — آپلود واقعی فایل نداره |
| PostgreSQL | SQLite (فایل `backend/ghalatazmoon.db`) |
| Redis / Celery broker | حذف شده — کاری که این‌ها انجام می‌دادن (صف async) این‌جا sync اجرا می‌شه |
| پاسخ تشریحی هوش مصنوعی در تست آموزشی | حذف شد — فعلاً فقط «عکس پاسخنامه» + یادداشت تشریحی خود کاربر نمایش داده می‌شه |

## اجرا
```bash
cd backend
pip install -r requirements.txt
python app.py
```
اولین اجرا، دیتابیس رو می‌سازه و درس‌های استاندارد کنکور (رشته‌های ریاضی و
تجربی) رو seed می‌کنه. بعد برو به: **http://127.0.0.1:5001**

از همون صفحه می‌تونی ثبت‌نام کنی، غلط ثبت کنی، تمرین/آزمون بسازی و جواب بدی —
همه‌چیز روی دیتابیس واقعی ذخیره می‌شه.

> ⚠️ اگر دیتابیس قدیمی (قبل از تغییر برنامه‌ی درسی) را داری، کافیست فایل
> `backend/ghalatazmoon.db` را پاک کنی تا با درس‌های جدید از نو ساخته شود.

## برنامه‌ی درسی (Curriculum)
فقط **درس‌ها** ثابت هستن — دقیقاً این فهرست، دسته‌بندی‌شده:

| رشته ریاضی | رشته تجربی |
|---|---|
| دسته شیمی: شیمی 1، شیمی 2، شیمی 3 | دسته زیست: زیست 1، زیست 2، زیست 3 |
| دسته ریاضیات: ریاضی 1، حسابان 1، حسابان 2، آمار و احتمال، گسسته | دسته شیمی: شیمی 1، شیمی 2، شیمی 3 |
| دسته هندسه: هندسه 1، هندسه 2، هندسه 3 | دسته فیزیک: فیزیک 1، فیزیک 2، فیزیک 3 |
| دسته فیزیک: فیزیک 1، فیزیک 2، فیزیک 3 | دسته ریاضی: ریاضی 1، ریاضی 2، ریاضی 3 |
| | دسته زمین‌شناسی: زمین‌شناسی |

**پایه، فصل و مبحث را خود کاربر موقع ثبت غلط تایپ می‌کند** (چون فهرست‌های
ثابت مباحث اشتباه بودن و یک کنکوری از هر سه پایه تست می‌زند).

## حالت‌های تمرین و آزمون
وقتی «تمرین و آزمون» باز می‌شود، اول از کاربر پرسیده می‌شود کدام حالت:

1. **تست آموزشی** — بعد از هر پاسخ، همان لحظه تصحیح می‌شود، عکس پاسخنامه‌ی
   سؤال نمایش داده می‌شود و بعد سه دکمه ثبت می‌شود:
   «کاملاً فهمیدم / نصفه‌نیمه فهمیدم و مرور نیاز دارم / اصلاً نفهمیدم».
   این بازخورد روی زمان‌بندی مرور فاصله‌دار (SRS) هم اثر می‌گذارد.
2. **تست پوششی** — کاربر تعداد مشخصی تست را یکسره و بدون دیدن پاسخ جلو می‌رود
   و در پایان همه را یکجا چک می‌کند.
3. **آزمون** — دو بخش:
   - **آزمون کامل**: قبل از ساخت می‌پرسد از چه پایه‌ای (دهم / یازدهم /
     دوازدهم / هر سه پایه مشابه کنکور) و بعد **دقیقاً مثل دفترچه‌های کنکور**
     ساخته می‌شود — هر دفترچه تعداد سؤال و زمان مخصوص خودش را دارد:
     - رشته ریاضی: دفترچه ریاضیات (سه‌پایه: 40 سؤال/70 دقیقه؛ تک‌پایه: 30/55)
       و دفترچه فیزیک‌وشیمی (سه‌پایه: 65/75؛ تک‌پایه: 40/45).
     - رشته تجربی: دفترچه زیست (سه‌پایه: 45/45؛ تک‌پایه: 30/30)، دفترچه
       فیزیک‌وشیمی (سه‌پایه: 65/75؛ تک‌پایه: 40/45) و دفترچه ریاضی‌وزمین
       (سه‌پایه: 45/60؛ دهم: 20/40؛ یازدهم: 30/40).
     - ترکیب دقیق هر دفترچه در `backend/services/full_exam_spec.py` است و با
       اندپوینت `GET /api/v1/exams/full-exam-spec/` هم قابل پیش‌نمایش است.
   - **آزمون شخصی‌سازی‌شده**: تعداد تست، زمان (یا بدون زمان)، درس‌ها، پایه‌ها
     و مبحث دلخواه.

### زمان‌بندی دفترچه‌به‌دفترچه
آزمون به ترتیب دفترچه‌ها شروع می‌شود؛ داخل هر دفترچه می‌توان بین سؤال‌های
**همان دفترچه** جابه‌جا شد. وقتی زمان دفترچه تمام شود یا کاربر «پایان دفترچه»
را بزند، دفترچه‌ی بعدی شروع می‌شود و این روند تا دفترچه‌ی آخر ادامه دارد
(پایان زمان یا «پایان آزمون»).

## ثبت غلط — قوانین
- «پاسخ صحیح» و «پاسخ من» **نمی‌توانند یکسان باشند**؛ هم در فرم (گزینه‌ی
  تکراری غیرفعال می‌شود) و هم در API (خطای 400) جلوی این حالت گرفته شده است.
- فیلدهای جدید: `base` (پایه)، `chapter_name`، `topic_name` (متن آزاد)،
  `answer_image_url` (عکس پاسخنامه)، `understanding` (بازخورد فهمیدن).

## بانک غلط‌ها — مرتب‌سازی
لیست غلط‌ها (`GET /api/v1/mistakes/`) با پارامتر `ordering` مرتب می‌شود
(پیشوند `-` یعنی نزولی): `created_at` (جدیدترین/قدیمی‌ترین)، `repeat_count`
(تعداد دفعات حل)، `understanding` (وضعیت فهمیدن)، `priority_score`،
`question_number` (شماره سؤال)، `lesson` (درس)، `base` (پایه)،
`chapter_name`، `topic_name`، `next_review_date`. صعودی و نزولی هر دو.

## ساختار
```
backend/
  app.py              نقطه‌ی ورود Flask، ثبت route‌ها، سرو کردن فرانت‌اند
  schema.sql           DDL کامل (پورت‌شده از بخش ۳ سند + ستون‌های جدید)
  db.py                اتصال sqlite + init + مایگریشن‌های سبک (ADD COLUMN)
  seed_data.py         درس‌های استاندارد کنکور (ریاضی/تجربی)
  auth.py              هش پسورد + صدور/اعتبارسنجی JWT
  utils.py             pagination و کمکی‌ها
  services/
    priority.py         فرمول priority_score (بخش ۵ سند)
    srs.py               زمان‌بندی مرور فاصله‌دار (بخش ۶ سند)
    exam_generator.py    تولید آزمون برای همه‌ی حالت‌ها (دفترچه‌محور)
    full_exam_spec.py    مشخصات دفترچه‌های آزمون کامل کنکوری
    weakness.py          تشخیص الگوی ضعف تکراری (بخش ۷ سند)
  routes/
    auth_routes.py، curriculum.py، mistakes.py، exams.py، analytics.py
frontend/
  index.html            SPA (تک‌فایل) — ثبت غلط با پایه/فصل/مبحث آزاد،
                         انتخاب حالت تمرین، تست آموزشی با پاسخنامه و ثبت فهم،
                         تست پوششی، آزمون کامل دفترچه‌به‌دفترچه با تایمر جدا،
                         آزمون شخصی‌سازی‌شده، بانک غلط‌ها با مرتب‌سازی
```

## اندپوینت‌های اصلی (`/api/v1/...`)
`auth/register|login|refresh|me`،
`lessons/`، `lessons/{id}/chapters/`، `chapters/{id}/topics/`،
`mistakes/` (CRUD + `due-today/` + `stats-summary/` + `{id}/understanding/`)،
`exams/generate|full-exam-spec|{id}|{id}/start|{id}/questions/{qid}/answer|.../flag|{id}/booklets/{idx}/finish|{id}/finish|{id}/result`،
`analytics/overview|by-lesson|by-chapter|trend|reason-breakdown|weak-topics`.
